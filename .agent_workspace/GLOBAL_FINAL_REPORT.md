## 一、执行摘要

**核心问题：微信小游戏双榜 Top 10 能否被复刻？**

**答案：机制普遍可复刻，产品普遍不可平移——这是两个必须分开回答的问题。**

1. **机制侧**：畅玩榜（IAA）头部游戏的核心玩法，用无引擎、无服务器、无美术资产的原生 JavaScript 即可完整复刻并自动化验证。本仓库用 4 个可运行原型给出了构造性证明：层叠三消核心 446 行、停车解谜全量可玩版 约 1,600 行（其中 BFS 求解器核心仅约 50 行）。畅销榜（IAP）头部的机制同样可移植，但 SLG 类的留存循环（联盟战争、持久世界）根本不存在于客户端，复刻它是一个后端工程计划而非项目。
2. **产品侧**：这些游戏的商业价值绑定在微信平台织物上——激励视频广告网络、分享复活/聊天卡片分发（头部产品 30–50% 新增来自社交分享）、开放数据域好友排行、一键登录与支付、免安装 <3 秒启动。这些没有站外等价物；22 款游戏的产品复刻分（P 轴）全部落在 2–5 分区间，无一例外。
3. **对独立开发者的可操作结论**：盯畅玩榜不要盯畅销榜；最佳落地目标是「挪了下车」家族（机制 10 分 + 产品 5 分，双榜最高组合）；羊了个羊/跳一跳类是「机制矿」——玩法几乎免费，但商业价值需在你自己的渠道（而非对微信的模仿）上重建。
4. **法律侧**：玩法规则不受著作权保护（有直接判例），但美术、名称、代码、关卡、文案必须 100% 原创；IAA 免版号路径是小团队/海外团队唯一的快速通道，IAP 需版号加国内主体。

> **时效性声明**：本报告全部榜单结论定格于 **2026 年 7 月** DataEye-ADX × 引力引擎联合月榜快照。畅销榜月度换血率达 31%，任何「Top 10」的保鲜期约为一个月量级；结论的方法论（双轴框架、四象限策略）比具体名次更耐久。

## 三、能否复刻？——双轴框架与四象限

Round 1 的单轴「复刻分」曾把跳一跳和向僵尸开炮都打成 7 分，而两者站外失败的原因完全相反（前者「一个周末能写完但没了好友榜就没有灵魂」，后者「要真开发但商业模式可平移」）。Round 2 把评分拆成 M/P 双轴（22 款游戏，子项加权，全部记录于 `round2/dual-axis-scores.json`），得到四个策略象限（阈值 M≥7、P≥4）：

| 象限 | 代表游戏 | 对复刻者的策略 |
|------|---------|---------------|
| **机制矿**（M≥7, P≤3） | 跳一跳 10/2、羊了个羊 10/3、向往的生活 9/2、永远的蔚蓝星球 8/3、灵画师 / 跃动小子 / 镇邪人 / 寻道大千 7/3 | 玩法几乎免费复刻，但在位者的商业价值是**平台锁定**的——连原厂自己在站外都做不到产品平价。挖走循环，把产品价值重建在你的渠道社交织物上（Telegram Mini Apps、Discord、Web 门户天梯）；**不要**尝试对标式商业复刻 |
| **可克隆可商业化**（M≥7, P≥4） | 挪了下车 10/5、挪了个挪 9/5、一找一个准 / 沙画消消 / 搬砖没我快 9/4、打个螺丝 / 我的花园世界 8/4、向僵尸开炮 / 赵云与阿斗 7/4 | 双轴同优：机制是原生 JS 领域，产品也能在站外活（求解器生成内容、社交耦合轻、全球有同类先例）。**挪-家族/排序休闲簇是独立团队真正出货的最佳标的** |
| **技术护城河**（M≤6, P≥4） | 抓大鹅 6/4（唯一成员） | 门槛是移动端 Web 3D 物理这种客户端技术而非平台；引擎辅助后 M=8 |
| **不建议复刻**（M≤6, P≤3） | 躺平发育 6/3、疯狂水世界 6/3、无尽冬日 4/2、三国：冰河时代 4/2 | 在线耦合循环 + 重后端/重运营。SLG 仅作商业案例研究 |

**为什么 P 轴普遍偏低（2–5 分，无一上 6）**：Round 1 差距分析（G1–G12）逐项对照了 `wx.*` 能力与通用 Web/移动栈，其中四项被判定为 🔴 无法等价替换——①好友社交图谱与开放数据域排行；②携带负载的聊天/群分享卡片（头部产品 30–50% 装机来源）；③国内开放 Web 上事实上不存在的激励视频广告经济；④下拉最近/侧边栏/搜索等习惯性再入口。这四项正是 IAA 头部产品的收入线和增长线本身。

## 四、四个原型证明了什么

四个原型全部零依赖、零构建、原创命名与绘制（无任何原作素材），统一通过 `scripts/run-all-prototype-tests.sh` 无头验证，平台调用统一走 `prototypes/shared/wx-shim.js`（29 组 `wx.*` API 的确定性 mock，19 项自测，真机宿主自动让位）。

### 4.1 逐原型证据

| 原型 | 对标 | 证明的命题 | 关键测量 |
|------|------|-----------|---------|
| `tile-trio/`（叠叠消） | 羊了个羊 | **榜首休闲游戏的"游戏部分"只是几百行原生 JS**——单文件实现完整循环：层级遮挡、七槽托盘、保证可解的发牌、三种广告门控道具、胜负判定 | 每关 300/300 次生成均含可赢线；贪心求解器通关率 98–100% / 85–92% / 50–60%（难度曲线故意陡峭）；4 项平台闭环断言（看完广告才发奖、跳过不发奖、分享复活走回流、好友榜渲染 8 行） |

### 4.2 跨原型发现（比单个原型更重要）

1. **机制复刻分 ≠ 产品复刻分，且证明是构造性的。** 羊了个羊的机制在本仓库被两次独立复刻到可验证标准；它的产品——激励视频道具、分享复活、好友排行、聊天内分发——全部是 `wx.*` 平台表面，一行都搬不走。这就是双轴框架存在的理由。
2. **变现闭环的形状差异是品类级的。** 三消的付费时刻是「分享复活」（自带病毒传播的免费库存）；步数限制的停车解谜没有可分享的失败状态，收入线整体塌缩到一个 API（`wx.createRewardedVideoAd` 门控的提示）。`limitForPar` 步数预算系数由此成为全库商业敏感度最高的单一常数——它决定玩家多久卡关一次，即广告多久播一次。
3. **搜索成本不是难度代理。** parking-jam 实测：19 步关卡搜索 9,368 状态，34 步关卡反而只搜 9,294——只有最短解长度与感知难度相关。难度**评级**已被求解器解决，难度**定向生成**（高难关卡产量）才是内容管线的真实成本。
4. **mock 的价值在于暴露缺口而非掩盖缺口。** wx-shim 忠实复现了真机的不便（`shareAppMessage` 无成功回调→分享复活必须挂在 `onShow`+`shareTicket` 回流上；看完才发奖的 `isEnded` 分支；iOS 虚拟支付历史封锁形状），并附带一张「mock 补不上的缺口矩阵」：开放数据域子上下文、真实广告填充与 eCPM、`code2Session` 服务端、微信侧分发、版号资格、真机性能——这些是平台属性，任何代码都补不上。

## 五、给独立开发者的建议

1. **选榜**：盯畅玩榜（IAA），不要盯畅销榜（IAP）。畅销榜头部是数十到上百人团队的长线运营产品，机制是其中最便宜的部分；畅玩榜头部是单人到几人可完成的确定性解谜，且 IAA 变现可走免版号路径。
2. **选品**（按本研究的量化结论）：
   - **要出货**：挪了下车/挪了个挪家族（M10/P5、M9/P5）——机制天花板 + 全库最高产品分，全球 Web 门户有同类生存先例；排序消除簇（沙画消消/搬砖没我快，M9/P4）作为换皮快速跟进项。
   - **要学习**：羊了个羊/跳一跳（M10）——用来练手可解性生成与难度曲线，不要指望复刻其商业成绩。
   - **要差异化技术**：抓大鹅方向（Three.js + Rapier 的移动 Web 3D 物理基准）——全休闲榜唯一的客户端技术护城河。
   - **不要碰**：SLG（无尽冬日/三国冰河类）与棋牌（版号资质最严 + 腾讯网络效应）。
3. **技术栈**：微信为必需目标 → Cocos Creator 3.x + TypeScript（引擎插件内置于微信客户端，不占 4 MB 首包）；仅验证玩法 → 原生 Canvas/Phaser 的 Web MVP（本仓库四个原型即此路线）。**任何情况下**：游戏核心保持平台中立，`wx.*` 只出现在适配层（本仓库 `platform`/shim 模式即模板），第二构建目标（H5/抖音）就是免费的额外分发。
4. **把管线当产品做**：对排序/停车/三消品类，求解器即内容管线（评级、par、提示、验收全从它出）；但要为高难关卡准备反向构造或已知难板扰动方案——生成-测试在难度顶端产量塌方（实测 25,000:1）。难度曲线（羊了个羊第 2 关 <1% 通过率是手工调的）与关卡量才是真护城河。
5. **变现设计要先于代码**：想清楚你的品类的「付费时刻」是分享型（自带增长）还是提示型（收入塌缩到激励视频一个点）；分享奖励必须挂在回流验证上而非分享调用上（`shareAppMessage` 真机无成功回调）；步数/时限预算系数是广告频次旋钮，上线后应 A/B。
6. **合规路线**（详见第六节）：无国内主体的团队走 IAA + ICP 备案（官方口径全流程约 13–37 个工作日，个人开发者可行）；IAP 需版号 + 国内公司主体，作为二期与持证发行合作。

> 本节为研究性规划参考，**不构成法律意见**。具体标题、主体、变现路径与司法辖区需专业审查。

### 6.1 知识产权：判例已画清边界

- **玩法规则不受著作权保护**——羊了个羊（简游）诉「麻了个麻」案（北京互联网法院，判决 2025 年公开）直接认定：三消/取牌玩法属于不受保护的抽象思想；构成侵权的是 **16 张牌面美术**的实质性近似（判赔 2.6 万元 + 禁令）；「X了个X」命名模式**不具有**排他性；不正当竞争主张未获支持。
- **但整体视听作品保护仍能抓住像素级近似的克隆**——其他中国判例中此类赔偿达到数千万元级。复刻的安全边界是：机制可借鉴，**美术、名称、代码、关卡、文本、音频、角色必须全部原创**，并留存独立创作证据、登记自己的软著。
- **商标**：避开与在榜产品混淆性近似的名称，立项前完成商标检索。
- **平台政策**：微信审核会拒绝其认定的「低质仿冒」——复刻必须换题材重做表达，而不是换皮。

### 6.2 监管：IAA 与 IAP 是两条完全不同的路

| 要求 | IAA（纯广告变现） | IAP（内购） |
|------|------------------|-------------|
| 版号（NPPA） | **不需要**（规划口径） | **必需**，需数月且需国内出版协作 |
| 软著 | 边缘情形才需要 | 必需 |
| ICP 备案 | 必需（约 7–20 个工作日） | 必需 |
| 主体资格 | 个人开发者可行 | **仅限公司/个体工商户**，个人无法开通虚拟支付 |
| 端到端时间（官方口径） | 约 13–37 个工作日 | 版号到手后约 9–22 个工作日 |
| 未成年人防沉迷 | 必需 | 必需（2026 年起弹窗标准强制） |

- **海外团队硬约束**：微信小游戏注册需中国大陆主体（或国内发行合作方）；无主体的替代路线是同一套构建发 H5/海外平台，放弃微信分发换取零牌照负担。
- **iOS 支付的 2025–26 转折**：2025 年 11 月苹果-腾讯「Mini Apps Partner Program」后，小游戏 iOS 端虚拟支付有条件开通（iOS 15+、微信 8.0.68+、基础库 3.10.3+，须用 `wx.checkIsSupportMidasPayment` 运行时探测，此前 iOS 端仅能广告变现）。按官方小游戏激励政策口径：符合条件的 Apple MAPP 内购收入基础开发者分成 70%，2026-12-31 前促销期预计分成 88%（即平台侧有效抽成约 12%），以苹果结算为准——这进一步拉大了微信站内相对站外的变现优势。小游戏支付的正典 API 命名为 `wx.requestMidasPayment` / `wx.requestMidasPaymentGameItem`（`wx.requestVirtualPayment` 属普通小程序 API 树，不适用于小游戏）。
- **平台常量速查**（Round 3 已按 2026-08-26 现行官方文档归一化，正典数据文件：[`platform-constants.json`](./platform-constants.json)，每条事实带 `linux-verified` / `source-cited` / `pending-devtools` 验证标签）：主包 ≤ 4 MB；主包 + 全部分包总上限 **30 MB**（旧「默认 20 MB / 开通虚拟支付 30 MB」规则已被现行文档取代，仅作历史保留——这解释了早期报告间的 20/30 出入）；独立分包 ≤ 4 MB；本地 KV 存储 10 MB/用户/游戏；缓存 + 用户文件默认 200 MB（可申请 1 GB）；生产网络仅限已备案 HTTPS/WSS 域名；禁止远程执行 JS。
