# R16 测试入口与预期

## 自动化入口

从仓库根目录执行：

```bash
node games/fucheng-life/tests/r16-crisis-replay.test.js
./scripts/run-fucheng-life-tests.sh
```

预期：R16 专项断言通过；全量测试汇总为 `0 failed`，命令退出码均为 `0`。

## 手工入口

从仓库根目录启动静态服务：

```bash
python3 -m http.server 8000
```

使用最新版桌面 Chrome 打开
<http://127.0.0.1:8000/games/fucheng-life/>，清除站点数据并打开 DevTools Console。
移动端回归使用设备模式，视口宽度设为 `390px`。

## 场景与预期

1. **危机刷新补弹与幂等**
   - 推进月份触发「本月危机」，在选择结果前刷新页面或重新进入仪表盘。
   - 预期：同一危机重新弹出；存档中的 `pendingModal` 保留可序列化事件载荷，危机后果尚未入账。
   - 确认一个选项后，预期后果、日志只结算一次且 `pendingModal` 清除；再次刷新不再补弹。

2. **O1 与人情讨债补弹**
   - 分别触发普通 O1 和 NPC 人情讨债强弹窗，在确认前用关闭入口退出，并刷新或重进。
   - 预期：关闭不等于放弃，待处理弹窗仍会补弹；确认后才清除，奖励、惩罚及关系变化均不重复入账。

3. **补弹优先级与单月弹窗帽**
   - 同时准备未领取的合约结算与 `pendingModal`，重新进入仪表盘；再单独保留 `pendingModal` 重进。
   - 预期：合约结算优先补弹；处理后待处理危机/O1 仍可恢复。危机/O1 补弹成功时占用当月强弹窗额度，不与新强弹窗叠层。

4. **快进内置确认**
   - 在桌面操作区与 `390px`「更多」抽屉分别点击「快进三月」。
   - 预期：两处均打开同一个游戏内确认面板，不出现浏览器原生 `window.confirm`；面板明确说明自动花 AP、不会自动探区及遇强弹窗会停止三条护栏。
   - 分别选择取消与确认；取消不推进月份，确认沿用既有快进规则，焦点和滚动在关闭后恢复。

5. **刷新与老存档回归**
   - 加载不含 `pendingModal` 字段的 R15 存档，再测试普通推进、快进和合约结算补弹。
   - 预期：迁移后 `pendingModal` 默认为 `null`，流程无报错；合约结算补弹优先级和既有幂等语义不变。

6. **桌面与移动端回归**
   - 桌面与 `390px` 各走一次「推进月份 → 触发危机/O1 → 刷新补弹 → 确认 → 快进三月」。
   - 预期：确认面板与事件弹窗无叠层、无横向溢出，主按钮可操作；Console 无 error、未处理 Promise rejection 或 404。
