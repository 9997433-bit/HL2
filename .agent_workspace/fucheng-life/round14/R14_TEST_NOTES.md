# R14 测试入口与预期

## 自动化入口

从仓库根目录执行：

```bash
node games/fucheng-life/tests/r14-flow-fixes.test.js
./scripts/run-fucheng-life-tests.sh
```

预期：R14 专项断言通过；全量测试汇总为 `0 failed`，命令退出码均为 `0`。

## 手工入口

从仓库根目录启动静态服务：

```bash
python3 -m http.server 8000
```

使用最新版桌面 Chrome 打开
<http://127.0.0.1:8000/games/fucheng-life/>，清除站点数据并打开 DevTools Console。
移动端回归使用设备模式，视口宽度设为 `390px`。

## 场景与预期

1. **快进三月**
   - 完成开局并进入仪表盘，不必先手动花 AP，点击「快进三月」并确认。
   - 预期：系统逐月自动花完 AP 后结算，最多连续推进 3 个月；每月的行动、收支和日志正常入账。
   - 任一月出现强弹窗，或没有合法行动可花完 AP 时，快进立即停止并留下原因提示；不得跳过弹窗、额外推进月份或重复结算。

2. **闯城目标与合约绑定**
   - 开四局「闯城 60 月」，依次选择「落户上岸」「攒够首付」「向上爬一层」「还清负债」，进入合约选择。
   - 预期：前三个目标分别将「落户积分」「攒首付」「升职」合约置顶并显示推荐标记，提示文案说明目标与合约应对齐；「还清负债」不强制推荐任何合约。

3. **单月强弹窗上限与优先级**
   - 推进到合约结算、合约要约和危机/O1 可在同月命中的状态；确定性覆盖以 R14 自动化用例为准。
   - 预期：该月只打开 1 个强弹窗，按「合约结算 > 要约 > 危机/O1」取最高优先级；关闭或处理后不得在同月继续叠出较低优先级弹窗。

4. **危机短窗去重**
   - 连续推进多个危机触发窗口，记录每次危机 id/标题。
   - 预期：候选池会避开 `recentCrisis` 中的近期 id；短窗内不重复同一危机，且冷静期和兜底触发仍可用。

5. **回归**
   - 桌面与 `390px` 各走一次「开局 → 选目标/合约 → 快进 → 处理弹窗 → 返回仪表盘」。
   - 预期：主按钮可操作、弹窗无叠层、页面无横向溢出，Console 无 error、未处理 Promise rejection 或 404。
