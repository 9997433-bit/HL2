# R17 测试入口与预期

## 自动化入口

从仓库根目录执行：

```bash
node games/fucheng-life/tests/r17-pending-contract.test.js
./scripts/run-fucheng-life-tests.sh
```

预期：R17 专项断言通过；全量测试汇总为 `0 failed`，命令退出码均为 `0`。

## 手工入口

从仓库根目录启动静态服务：

```bash
python3 -m http.server 8000
```

使用最新版桌面 Chrome 打开
<http://127.0.0.1:8000/games/fucheng-life/>，清除站点数据并打开 DevTools Console。
移动端回归使用设备模式，视口宽度设为 `390px`。

## 场景与预期

1. **合约门禁 O1 刷新补弹**
   - 触发一张带 `contract` 字段、具有 `id` 与 `choices` 的 O1，在选择结果前关闭或刷新页面。
   - 预期：该卡写入 `pendingModal`，重进后以同一载荷补弹；确认前无后果入账，确认后清除待办，奖励、惩罚与日志只结算一次。

2. **合约结算卡排除**
   - 分别触发显式 `{ pending: false }` 的合约结算卡与 `resolutionEvent` 产物，再刷新或重新进入仪表盘。
   - 预期：两类结算事件不写入 `pendingModal`，继续沿用合约结算自身的领取与幂等流程；普通合约 O1 不会因存在 `contract` 字段而被误排除。

3. **开局补弹收敛**
   - 分别准备未领取的合约结算和待补弹的 `pendingModal` 后重进仪表盘，并覆盖尚未选轨、尚未签约或尚未看教学的存档。
   - 预期：本次启动先恢复已有待办，并推迟自动选轨、签约与聚光灯教学，不出现连续强弹窗；返回仪表盘后手动教学按钮仍可用。

4. **闯城主目标防软锁**
   - 使用缺少主目标的闯城档触发开局补弹路径。
   - 预期：即使本次启动发生合约结算或 `pendingModal` 补弹，系统仍会要求选择闯城主目标，目标流程不被永久跳过。

5. **危机池扩容与既有护栏**
   - 连续推进多组月份，抽查新增危机的标题、二选一选项和结果，并记录触发间隔与近期危机 id。
   - 预期：危机池新增 2–3 条写实事件；触发仍经过概率闸，避开 `recentCrisis`，且不突破每月一个强弹窗上限。

6. **桌面与移动端回归**
   - 桌面与 `390px` 各走一次「开局补弹 → 确认事件 → 推进月份 → 触发危机 → 手动重开教学」。
   - 预期：弹窗无叠层、无横向溢出，主按钮和教学入口可操作；Console 无 error、未处理 Promise rejection 或 404。
