# R18 测试入口与预期

## 自动化入口

从仓库根目录执行：

```bash
node games/fucheng-life/tests/r18-stale-contract.test.js
./scripts/run-fucheng-life-tests.sh
```

预期：R18 专项断言通过；全量测试汇总为 `0 failed`，命令退出码均为 `0`。

## 手工入口

从仓库根目录启动静态服务：

```bash
python3 -m http.server 8000
```

使用最新版桌面 Chrome 打开
<http://127.0.0.1:8000/games/fucheng-life/>，清除站点数据并打开 DevTools Console。
移动端回归使用设备模式，视口宽度设为 `390px`。

## 场景与预期

1. **有效合约门禁补弹回归**
   - 准备一份当前合约仍有效、`pendingModal` 挂有匹配 `contract` 门禁事件的存档，然后刷新或重新进入仪表盘。
   - 预期：同一张卡正常补弹；确认前不入账，确认选项后清除待办，奖励、惩罚、合约进度与日志均只结算一次。

2. **过期合约门禁销账**
   - 准备一份带 `contract` 字段的待补弹事件，再让对应合约结算、失效或与当前合约不匹配后重进仪表盘。
   - 预期：系统重验门禁后不打开过期卡，清除 `pendingModal`，卡片选项后果不入账，并新增一条说明该待办已失效的系统日志。
   - 再次刷新，预期不再补弹、不重复写系统日志，也不产生现金、KPI、合约进度或其他选项变化。

3. **选轨手动入口**
   - 使用 `needsPick` 为真的存档，并通过开局补弹路径推迟自动选轨。
   - 预期：仪表盘显示「选择职业轨道」按钮；点击后复用既有职业轨道选择面板，选定轨道后职场信息更新，按钮随 `needsPick` 变为假而隐藏。

4. **教学 KEY 政策**
   - 先写入已读键 `fucheng.guide.v7`，再加载包含本轮增量文案修正的页面。
   - 预期：教学不会因文案小改自动重弹，存储键仍为 `fucheng.guide.v7`，不创建或读取 v8；手动入口与重置后重看仍可用。
   - 核对 SOP：增量文案默认不 bump KEY，仅步骤、目标或交互流程等结构性改版才升版。

5. **桌面与移动端回归**
   - 桌面与 `390px` 各走一次「开局补弹被销账 → 手动选轨 → 手动重看教学 → 推进月份」。
   - 预期：系统日志可读，选轨入口不被遮挡且无横向溢出；弹窗、合约、教学和推进流程无回归，Console 无 error、未处理 Promise rejection 或 404。
